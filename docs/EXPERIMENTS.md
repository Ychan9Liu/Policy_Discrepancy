## 已确认的实验设计边界

- 主问题为 M2：Dt 是否提供优于统一减弱 rep KL 的逐时刻选择信号。
- 首版使用参考定义，只支持本仓库标准 categorical RSSM 与连续 bounded_normal actor。
- 至少 baseline、Dt、预先校准并冻结的常数权重、全局打乱四组；更强 M2 再加入条件打乱。基础四组不自动排除活跃性/KL 大小等混杂。
- mode 漏检、早期不敏感、干扰误敏感与延迟线索列为局限并诊断，首版暂不叠加修复。
- 先固定任务、观测通道、校准规则、主指标、训练 seed 和预算，再确定 alpha 与效果判据；alpha/c 与判据在正式比较结果产生前冻结。
- 首轮任务已确认：`dmc_hopper_hop`、`dmc_quadruped_run`、`dmc_quadruped_walk`、`dmc_reacher_hard`；四者均 `image=True`、`proprio=False`、clean 环境。尚未指定四者中的单一优先任务或任务权重。
- 尚未确认：实际 baseline 配置与提交、训练/评估环境 seed 路径、校准窗口/seed/统计量/目标权重、常数匹配口径、主指标、训练 seed 列表、预算、alpha/c、效果阈值与统计方法。没有正式运行或 M2 结果。
- 条件打乱只在提出更强 M2 时补充；分层、区间、边界和退化处理协议仍未定，不阻塞基础四组方法实现。

## 协议字段

四个真实 DMC 环境已在三台服务器完成创建与步进烟测；这不等于模型训练/评估可运行。DMC 环境 seed 传递路径已补上，须通过端到端运行验证。先固定可复现 baseline 与 logging-only 校准规则，再冻结评价协议和预算，之后按预定规则计算并冻结 alpha/c。return AUC、活跃位置平均权重匹配和先用三个训练 seed 筛查均为候选方案，尚未成为正式协议。

正式实验前固定：任务及环境版本、baseline、方法配置、训练步数或交互预算、seed 列表、评价频率与指标、GPU 分配、模型规模、停止与续跑规则。对照实验仅改变预先声明的变量。

每次运行保存：运行编号、Git commit、实际 `config.yaml`、环境依赖快照、服务器与 GPU、seed、启动命令、开始与结束时间、退出状态、指标文件和检查点位置。不同运行使用不同 `logdir`；只有明确续跑才复用。
