# Codex 聊天分工

本项目以 `D:\program\PD\dmr3` 为代码和文档根目录。聊天用于推进工作，仓库文件用于跨聊天交接；新聊天先读取与其任务相关的文档，不依赖其他聊天的完整历史。

| 聊天 | 职责 | 主要事实来源与产出 | 首选交接方向 |
| --- | --- | --- | --- |
| 01 · Idea 讨论 | 梳理研究问题、文献线索、可证伪假设和反例；标明尚未确认的想法 | `docs/RESEARCH.md` | 将需要定义或取舍的方法问题交给 02 |
| 02 · 方法与机制 | 明确数学定义、已确认设计、机制预测、消融与实验协议；保留未决问题 | `docs/METHOD_SPEC.md`、`docs/RESEARCH.md`、`docs/EXPERIMENTS.md` | 将已确定的实现与验收规范交给 03；协议缺项先在 02 解决 |
| 03 · 代码与测试 | 按已确认规范实现方法和工程链路，记录提交、fixture、完整 agent 验收与限制 | 代码、测试、`docs/CODE_PHASE1.md`、`docs/CODE_PHASE2.md`、`docs/CODE_PROTOCOL_V1.md`、`docs/STATUS.md` | 将确定提交、运行配置、验收证据及剩余工程条件交给 04；测试发现方法歧义交回 02 |
| 04 · 服务器实验 | 核对提交、配置、环境和资源，按已确认协议执行工程试跑或获授权的正式运行，记录故障与产物 | `docs/EXPERIMENTS.md`、`docs/STATUS.md`、服务器 `/data/Policy_Discrepancy/runs` 独立目录 | 将完整运行索引和质量检查交给 05；代码故障交回 03，协议歧义交回 02 |
| 05 · 实验分析 | 汇总指标、检查异常、比较对照并说明证据边界；不把描述性结果写成跨 seed 结论 | `docs/EXPERIMENTS.md`、`analysis/` | 将新的机制或协议问题交回 02，缺失/异常运行交回 04，分析发现的实现问题交回 03 |

交接按当前任务实际进度选择一个首选下一步，不自动推进到下一阶段。每次最终回复的交付、证据、下一步和可复制 prompt 遵循根目录 `AGENTS.md`；由用户决定继续现有 chat 或手动创建新 chat，不自动创建或向其他 chat 发消息。一次具体代码改动或正式实验可以另开短任务，标题写清任务、方法与运行编号；阶段聊天保留决策脉络。科研内容未定时，各聊天只建立边界，不替用户选择任务或方法。当前协议与进展以 `docs/EXPERIMENTS.md`、`docs/STATUS.md` 和确定提交为准，不以此表或聊天摘要替代。
